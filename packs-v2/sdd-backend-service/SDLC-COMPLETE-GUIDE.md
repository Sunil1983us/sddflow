# Complete SDLC Guide
# SDD 6-Verb Workflow — Constitution Generated from Context

---

## The Core Idea

You write what the system does (context.md).
Agent generates everything else — automatically.

```
context.md (you write)
    ↓
SPECIFY → reads context → generates constitution Part 2
                       → generates BRD, SRD, HLD...
    ↓
ANALYZE → risks + complexity
    ↓
CLARIFY → resolve ambiguities (you answer)
    ↓
PLAN → architecture + design
    ↓
TASK → Feature → Story → Task + Jira
    ↓
IMPLEMENT → code one task at a time
```

---

## The 3 Files You Own

### 1. manifest.yml (2 min)
```yaml
project:
  name: "Your Service"
  scope: "pilot"
  feature: "feature-name"
  context_file: "feature-name.md"
pr_rules:
  max_lines_per_pr: 400
  max_files_per_pr: 5
```

### 2. contexts/{feature}.md (15-30 min)
Your system description. Must include tech stack section.
Agent extracts constitution from this — the richer it is, the better.

### 3. constitution.md Part 1 only
Part 1 is pre-filled universal rules — never edit.
Part 2 is generated by SPECIFY — never fill manually.

---

## SPECIFY — Two Actions

**Action 1 — Generate constitution Part 2:**
Agent reads your context and extracts:
- Tech Stack (20 concerns: Language, Framework, Database, CI/CD...)
- Core Principles (derived from your domain)
- Domain Rules (from your business rules)
- Never Do (from your constraints)

**Action 2 — Generate spec documents:**
BRD → SRD → Analyze → HLD → API Spec → Data Model

---

## 6-Verb Gates

| Gate | Requirement |
|---|---|
| Before CLARIFY | ANALYZE complete + reviewed |
| Before PLAN | clarify.summary.md exists (all items resolved) |
| Before TASK | PLAN approved |
| Before IMPLEMENT | stories.md + tasks.md both approved |

---

## PR Rules

Every task:
1. Agent estimates lines
2. If > max_lines_per_pr → SPLIT A/B/C → confirm → one at a time
3. After task → state files + lines → wait for go

---

## Feature → Story → Task (TASK verb)

```
FEATURE (business capability — from BRD)
  └── STORY (As/I want/So that — from SRD FRs)
        ├── Acceptance criteria
        ├── Story points
        └── TASK (one PR each)
```

Jira CSV generated at TASK verb — import before implementation.

---

## Change Management

Rule: **context.md first — always.**

```
Update context.md + CHANGELOG
→ Run SPECIFY for affected docs only
→ Run ANALYZE if risk profile changed
→ Run CLARIFY for new ambiguities
→ Append CHG-NNN tasks
→ Implement CHG tasks (same PR rules)
```

---

## Scope Progression

```
pilot → mvp → full
Each upgrade: edit manifest scope + tell agent
"Scope upgraded — generate newly enabled docs only"
```

## Full Checklist

### Setup
- [ ] Pack copied to project
- [ ] manifest.yml filled (4 fields)
- [ ] context.md written with tech stack section
- [ ] Git initialised

### SPECIFY
- [ ] Constitution Part 2 generated and reviewed
- [ ] Tech Stack table complete (all 20 concerns)
- [ ] All spec documents generated + .summary.md
- [ ] BRD + SRD + HLD reviewed

### ANALYZE
- [ ] Risk register complete
- [ ] Complexity hotspots identified
- [ ] Dependencies mapped
- [ ] Reviewed before CLARIFY

### CLARIFY
- [ ] All AMB, GAP, CON, ASM, OQ, HR items answered
- [ ] clarify.summary.md written

### PLAN
- [ ] Architecture reviewed
- [ ] HLD diagrams correct
- [ ] Plan approved before TASK

### TASK
- [ ] Feature + stories make business sense
- [ ] All tasks have estimated lines
- [ ] Over-limit tasks marked SPLIT
- [ ] Jira CSV ready for import
- [ ] stories.md + tasks.md approved

### IMPLEMENT
- [ ] Each task estimated before coding
- [ ] Each PR under line + file limits
- [ ] Paired test in every PR
- [ ] All acceptance criteria confirmed per task
- [ ] Tests passing before merge

### Change
- [ ] context.md updated FIRST + CHANGELOG
- [ ] Only affected documents updated
- [ ] CHG tasks appended + implemented
